Статус: локальный build candidate, не релиз. Публикация запрещена до заполнения этого чек-листа.

- Текущий candidate находится в `.local-build-artifacts`; GitHub release/tag не создавался.
- `ZUI_2.1.1_portable.zip`: SHA-256 `465bc12e4bda4e62e147dcd1de8cc40e3a407085b07a58ae11e31b97c3fc244c`.
- `ZUI_2.1.1_x64-setup.exe`: SHA-256 `044251a64e3dab145474699e47bee891cc84eedb916b578ce46980a3d2838d71`.
- `ZUI_2.1.1_x64_en-US.msi`: SHA-256 `175610cc605a6cf61f6a214cd43c8033da325db8edf78efef4f85d2390866b25`.
- Закрыть другие сборки ZUI, `winws.exe`, `winws2.exe` и сторонние DPI/proxy-приложения.
- Сохранить важные настройки текущей установленной версии.
- Проверять сначала portable, затем NSIS, затем MSI на отдельной тестовой установке.
- Для сетевых проверок записать провайдера, тип подключения, дату и выбранный пресет: результат зависит от DPI и региона.

## 1. Целостность build candidate

- [ ] Хэши файлов совпадают с `.local-build-artifacts/SHA256SUMS.txt`.
- [ ] `ZUI.exe` показывает FileVersion и ProductVersion `2.1.1`.
- [ ] В portable есть `portable.flag`, `resources/zapret`, `resources/zapret2` и `data/profiles.json`.
- [ ] В `resources/zapret2/manifest.json` указана engineVersion `1.0.4`.
- [ ] В portable присутствуют новые v1.0.4 payloads: `bgp_open.bin`, `discord-ip-discovery-with-port.bin`, `dtls_serverhello.bin`, `tls_serverhello_google_com_tls13.bin`.

## 2. Portable и базовый UI

- [ ] Распаковать `ZUI_2.1.1_portable.zip` в новую пустую папку.
- [ ] Запустить `ZUI.exe`, подтвердить UAC; окно открывается без консоли и ошибок.
- [ ] В «О ZUI» указана версия `2.1.1`.
- [ ] Старые изображения из `image/` не использовать как эталон; проверить фактическую компоновку, русский и английский языки, светлую и тёмную темы.
- [ ] В общих настройках работают переключатели «Запускать ZUI вместе с Windows», «Автозапуск активного профиля» и «Проверять обновления при запуске»; после перезапуска значения сохраняются.
- [ ] Закрытие, сворачивание и tray работают; после Quit процесс ZUI отсутствует.
- [ ] При уже открытом ZUI повторный запуск EXE не создаёт второй процесс/окно, а разворачивает, показывает и фокусирует существующее главное окно (проверить также из свернутого состояния и tray).
- [ ] Данные создаются рядом с portable EXE, а не в `%APPDATA%\ZUI`.

## 3. Профиль и настройка tg-ws

- [ ] В новом профиле host/port — `127.0.0.1:1443`, Secret состоит из 32 hex-символов; кнопка обновления создаёт новый Secret и обновляет preview Telegram-ссылки.
- [ ] Preview Telegram Secret равен `dd` + 32-символьный Secret профиля. `dd` — служебный MTProto-префикс, оставшиеся 32 символа должны совпадать точно.
- [ ] Очистить Secret, дождаться сохранения и перезапустить ZUI: профиль получает один новый 32-символьный Secret, который сохраняется и больше не меняется самопроизвольно.
- [ ] Поле DC → IP принимает по одному правилу `номер:IP` на строку; неверный IP даёт понятную ошибку запуска, корректные значения сохраняются после перезапуска.
- [ ] CF Proxy включён по умолчанию и использует автоматические домены; переключатель «Свой домен» реально заменяет автоматический список пользовательским.
- [ ] Кнопка `Тест` CF Proxy проверяет DC 1/2/3/4/5/203, показывает отдельный результат каждого DC и не требует запуска локального tg-ws.
- [ ] Для заведомо неверного CF-домена тест завершается FAIL, а не ложным успехом после обычного HTTPS-ответа.
- [ ] Включить Worker, указать один и несколько доменов; Worker test проверяет все шесть DC и отправляет MTProto-init через туннель.
- [ ] Для Worker, который отвечает `101`, но не может подключиться к Telegram, тест должен завершиться FAIL после проверки MTProto-туннеля.
- [ ] `buf_kb`, размер пула, verbose, максимум лога и `force_test_dc` сохраняются и передаются движку; параметры заблокированы во время работы сервиса.
- [ ] При достижении лимита `tg-ws.log` предыдущий файл переименовывается в `tg-ws.log.1`, новый лог продолжает записываться.
- [ ] В `Настройки → Сервисы → Расширенная маршрутизация` видно поле `SNI для domain fronting`.
- [ ] В новом профиле значение по умолчанию — `sprinthost.ru`.
- [ ] Изменить значение, перезапустить ZUI и убедиться, что оно сохранилось.
- [ ] Очистить поле, перезапустить ZUI и убедиться, что fronting остался выключенным.
- [ ] Старый профиль без `tgWsFrontingDomain` загружается без ошибки и получает безопасное default-поведение.
- [ ] Несколько Worker domains через запятую/точку с запятой сохраняются и не дублируются при запуске.

## 4. tg-ws — локальный запуск

- [ ] Включить только tg-ws без выбранного zapret-пресета: сервис запускается.
- [ ] Статус становится Running, появляется корректная `tg://proxy` ссылка на настроенный адрес (для нового профиля `127.0.0.1:1443`).
- [ ] Telegram принимает ссылку и подключается к локальному proxy.
- [ ] При включенном профиле полностью выйти из ZUI, затем снова запустить его: последнее включенное состояние восстанавливается, listener появляется на том же host/port, Telegram Secret не меняется и Telegram переподключается без повторного добавления proxy.
- [ ] Нажать Power Off, закрыть и снова запустить ZUI: явно выключенный профиль не должен запускаться через механизм восстановления последнего состояния (если отдельно не включен профильный/глобальный автозапуск).
- [ ] Текстовые сообщения, изображения, голосовые сообщения, скачивание и отправка файлов работают.
- [ ] Проверить отправку и скачивание файла заметно больше 1 MiB через Cloudflare Worker; соединение не обрывается.
- [ ] Проверить direct route, CF proxy domain, несколько Worker domains, CF priority и CF balance по отдельности.
- [ ] На сети, где прямой WSS блокируется, сравнить `sprinthost.ru` и пустое fronting-поле; в логах должен быть понятен выбранный fallback.
- [ ] После Stop порт освобождается, Telegram-ссылка перестаёт считаться активной, фонового tg-ws процесса нет.
- [ ] При занятом порту появляется понятная ошибка, чужой процесс не завершается.
- [ ] Только на тестовом Telegram-аккаунте включить `force_test_dc`: DC 1-3 идут на test IP и `/apiws_test`; затем выключить параметр и убедиться, что обычный аккаунт снова работает.
