# Ручная проверка Network Tester v2 — этап 2

Тестовая сборка: `2.2.4-network-test.2`.

## Подготовка

1. Закрыть работающий `winws.exe`/`winws2.exe`.
2. Запустить ZUI от имени администратора.
3. Открыть `Настройки → Проверка сети`.
4. Убедиться, что в целях появились Discord Gateway API/WebSocket, YouTube media, HTTP/1.1, HTTP/2, TLS 1.2, TLS 1.3, QUIC/HTTP3 и UDP.

## Основной сценарий

1. Запустить проверку одного заведомо рабочего пресета.
2. Открыть подробности результата.
3. Для HTTP-целей проверить наличие этапов DNS, TCP, TLS, HTTP и CONTENT.
4. Проверить, что показываются фактические HTTP/TLS/ALPN, конечный адрес, Content-Type, объём ответа и задержка.
5. В карточках Discord и YouTube проверить матрицу Web/API, CDN/media, WebSocket, UDP/voice, HTTP/3 и Transport.
6. У Discord Gateway WebSocket успешный результат допустим только после HTTP 101 и Hello opcode 10.
7. YouTube не должен получить полный статус, если media range не выполнен.

## Защита от ложного успеха

1. Добавить пользовательскую цель, возвращающую HTTP 404: результат должен быть `Fail`, причина — HTTP.
2. Добавить цель с HTTP 403: результат должен быть `Fail`, а не успешная доступность.
3. Для HTTP 429 результат должен быть `Неопределённо`.
4. При редиректе на чужой домен результат должен быть `Fail` с причиной несовпадения конечного домена.
5. Страница с текстом блокировки или captive portal не должна считаться успешной даже при HTTP 200.
6. CAPTCHA/anti-bot должна отображаться как `Неопределённо`.

## Протоколы

1. HTTP/1.1 и HTTP/2 должны отображаться отдельными строками.
2. TLS 1.2 и TLS 1.3 должны отображать реально согласованную версию.
3. QUIC/HTTP3 не должен влиять на TCP/HTTPS: timeout QUIC не делает HTTPS неуспешным.
4. Если UDP/443 блокируется сетью, HTTP/3 получает отдельный `Fail` на стадии QUIC.
5. Discord voice остаётся `Неопределённо`, потому что безопасная voice-проба требует авторизованной сессии; ZUI не использует токен пользователя.
6. YouTube QUIC/HTTP3 отображается в группе YouTube отдельно от общей Cloudflare-пробы.

## Baseline и сохранение

1. Сравнить одинаковую цель до и после пресета — изменение должно определяться по стабильному ID цели.
2. Открыть результат первого этапа после обновления — он должен загрузиться без ошибки.
3. Экспортировать и импортировать результаты новой схемы.
4. Проверить миграцию сохранённого набора целей: старые встроенные цели заменяются новыми, пользовательские сохраняются.

## Контролируемый ZUI endpoint

1. Развернуть `probe-worker` по инструкции в его README.
2. Выполнить healthcheck для `/health`, `/json` и Range.
3. Собрать ZUI с переменной `ZUI_PROBE_BASE_URL`.
4. Убедиться, что появилась диагностическая группа `ZUI Probe` с JSON, redirect, Range, WebSocket echo, HTTP/1.1, HTTP/2 и QUIC/HTTP3.
5. Проверить, что отключение Worker не влияет на статус Discord и YouTube.

## Критерий прохождения

- Нет ложного успеха для 403/404/429, блок-страниц и CAPTCHA.
- Discord Gateway подтверждён API и реальным WebSocket Hello.
- YouTube требует Web и media-проверку для полного статуса.
- Ответ каждого HTTP probe ограничен 64 КиБ.
- QUIC, UDP и WebSocket показываются независимо от HTTPS.
- Автоматические проверки `npm run check`, `npm run build`, `cargo test`, `cargo clippy` проходят.
