# Проверка tg-ws upstream — 2.2.4-network-test.5

Распаковать portable в отдельную папку. Сначала проверить чистый профиль; для проверки переноса настроек использовать копию старой папки data. Рабочую копию настроек сохранить.

## 1. Старое поведение

1. Запустить ZUI, включить tg-ws и подключить Telegram через ссылку ZUI.
2. В расширенных настройках убедиться, что H2 и Cloudflare без TLS выключены, прямые DC включены.
3. Отправить сообщение, открыть фотографии/видео, скачать файл.
4. Проверить остановку и повторный запуск tg-ws. После остановки его Telegram-прокси не должен работать.

## 2. HTTP/2

1. Остановить tg-ws. Включить Cloudflare Proxy и «Медиа через HTTP/2» в расширенных настройках. Оставить TLS включённым.
2. Запустить tg-ws. В журнале должны появляться маршруты `media -> H2 CF proxy`.
3. Открыть несколько новых фотографий, видео, затем скачать файл 100–500 МиБ. Проверять новые данные, не только кэш Telegram.
4. Запустить несколько загрузок одновременно. Убедиться, что сообщения продолжают приходить.
5. На 2–3 минуты прервать сеть, затем восстановить. Загрузка должна продолжиться после переподключения; ошибки не должны бесконечно накапливать RAM.
6. Выключить ZUI во время загрузки, запустить снова. Остановка должна укладываться в штатный дедлайн, повторный запуск — поднимать рабочий proxy.
7. Сравнить такой же файл и сеть при выключенном H2. Записать скорость, пиковую/обычную RAM и возможные зависания.

Текстовые/non-media соединения и test DC продолжают использовать прежние маршруты. В журнале раз в минуту есть счётчики `h2`: opened/reused/active, requests/replays/errors, transport_errors/fallback и учтённые буферы.

## 3. Cloudflare без TLS

1. Остановить tg-ws и включить «Cloudflare без TLS».
2. H2-переключатель становится недоступным: активен порт 80 для CF Proxy/Worker, MTProto внутри остаётся зашифрованным.
3. Выполнить кнопкой проверку CF-доменов; проверить Telegram.
4. Если есть собственный Worker — повторить для него.
5. Вернуть TLS. Домены, принудительно перенаправляющие HTTP на HTTPS, в plaintext-режиме могут не работать.

## 4. Прямые DC и fallback

1. Очистить поле DC→IP и сохранить профиль. Перезапустить приложение: DC2/DC4 не должны восстановиться.
2. Включить CF Proxy, проверить доступ через CF.
3. Вернуть DC→IP, затем выключить переключатель прямых подключений: значения сохраняются, но прямой WS-маршрут не применяется.
4. При недоступном TCP fallback журнал показывает пропуск попыток по backoff, без постоянного шторма подключений.

## 5. Перенос старых профилей

1. Заменить data в отдельной тестовой папке копией старой data.
2. Убедиться, что secret, порт, CF-домены и DC→IP сохранены.
3. Новые настройки по умолчанию: direct DC включён, H2 и plaintext CF выключены.
4. Изменить настройки, перезапустить ZUI и проверить сохранение переключателей.

Для отчёта достаточно: версия Telegram Desktop, H2 вкл/выкл, CF automatic/custom/Worker, скорость одного файла, RAM до/во время/после и фрагмент журнала с ошибкой. Не прикладывать proxy secret.
