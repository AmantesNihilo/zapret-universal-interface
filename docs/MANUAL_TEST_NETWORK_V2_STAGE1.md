# Ручная проверка ZUI 2.2.3-network-test.1

## Что проверяет эта сборка

Сборка содержит первый этап Network Tester v2: baseline без Zapret, настоящий DNS A/AAAA по UDP с TCP fallback, классификацию этапов ошибок, статусы passed/failed/inconclusive/cancelled, контроль процесса winws/winws2, единый Rust-манифест целей и взвешенный рейтинг.

HTTP-содержимое, Discord WebSocket, YouTube media и QUIC относятся ко второму этапу и в этой сборке ещё не являются полноценными прикладными проверками.

## Подготовка

1. Закройте стабильную ZUI и убедитесь, что `winws.exe` и `winws2.exe` не запущены.
2. Сохраните резервную копию пользовательской папки `data`, если тест выполняется поверх основной portable-папки.
3. Предпочтительно распаковать portable ZIP в отдельную папку.
4. Запустить `ZUI.exe` от администратора.
5. В разделе «О программе» проверить версию `2.2.3-network-test.1`.

## Сценарий A — манифест и валидация целей

1. Открыть Настройки → Тестирование → Изменить цели.
2. Нажать сброс целей.
3. Убедиться, что присутствуют группы Discord, YouTube, Google, Cloudflare и DNS.
4. В DNS должны быть цели вида `DNS:SYSTEM:discord.com`, `DNS:1.1.1.1:discord.com`, `DNS:8.8.8.8:youtube.com`.
5. Попробовать добавить `https://user:password@example.com` — backend должен отклонить цель.
6. Попробовать добавить `DNS:not-an-ip:discord.com` — backend должен отклонить цель.
7. Добавить `DNS:1.1.1.1:example.com` — цель должна сохраниться.

Критерий: стандартный список приходит из приложения, не содержит старых DNS-ping целей, некорректные значения не сохраняются.

## Сценарий B — обычный быстрый тест

1. Выбрать заведомо рабочий пресет.
2. Запустить тест одного пресета.
3. Первой фазой должна появиться «Проверяем сеть без zapret».
4. После baseline должен запуститься winws/winws2, затем начаться проверка пресета.
5. Дождаться завершения и открыть детали результата.

Проверить:

- присутствует блок «Исходное состояние сети»;
- показаны количества успешных, ошибочных и неопределённых baseline-проверок;
- отображается короткий fingerprint сети;
- DNS-строки имеют тип DNS, а не Ping;
- каждая проверка показывает изменение: доступно до и после, разблокировано, недоступно в обоих случаях либо регрессия;
- ping не увеличивает и не уменьшает основной рейтинг;
- после теста процессы winws/winws2 остановлены.

## Сценарий C — сравнение до и после

1. Выбрать пресет, который реально меняет доступность хотя бы одного сервиса в текущей сети.
2. Запустить быстрый тест.
3. В деталях найти проверки со статусом «Разблокировано пресетом».
4. Запустить заведомо неподходящий пресет.
5. Сравнить статусы и итоговый рейтинг.

Критерий: приложение не выдаёт обычный сетевой сбой за доказательство эффективности пресета; результат содержит явное сравнение baseline и preset.

## Сценарий D — отсутствие сети

1. Отключить сетевой адаптер или соединение до запуска теста.
2. Запустить тест.
3. Дождаться baseline и результата либо отменить после появления достаточного числа ошибок.
4. Включить сеть обратно.

Критерий: ошибки видны уже в baseline, а результат после пресета отмечается как «Недоступно до и после», а не «Разблокировано». Приложение остаётся отзывчивым и корректно очищает процессы.

## Сценарий E — DNS

1. При обычной сети проверить системный DNS и прямые серверы 1.1.1.1, 8.8.8.8, 9.9.9.9.
2. Если провайдер блокирует прямой UDP/53, прямые проверки могут быть failed/inconclusive, но системный DNS должен оцениваться отдельно.
3. Добавить пользовательскую цель `DNS:[2606:4700:4700::1111]:example.com`, если в сети есть IPv6.

Критерий: вывод содержит реальные A/AAAA DNS-результаты и отдельные причины NXDOMAIN, timeout, SERVFAIL или REFUSED.

## Сценарий F — аварийное завершение процесса

1. Запустить тест пресета.
2. После перехода к сетевым проверкам завершить принадлежащий тесту `winws.exe` или `winws2.exe` через Диспетчер задач.
3. Дождаться реакции ZUI.

Критерий: ZUI прекращает учитывать последующие сетевые ошибки как обычные, показывает ошибку этапа PROCESS и предупреждение о завершении процесса вне ZUI. Частичный результат сохраняется. При пакетной проверке следующий пресет не запускается, а вся тестовая сессия завершается. Итоговый рейтинг не становится рекомендованным, после теста не остаются принадлежащие ZUI процессы.

## Сценарий G — отмена

1. Запустить быстрый тест и отменить во время baseline.
2. Повторить и отменить во время запуска процесса.
3. Повторить и отменить во время сетевых проверок.

Критерий: интерфейс выходит из состояния тестирования, временные данные очищаются, winws/winws2 не остаются запущенными, сохранённая история не получает незавершённый быстрый результат.

## Сценарий H — небольшой пакетный тест

1. Выбрать 3–5 пресетов.
2. Запустить пакетный тест.
3. Убедиться, что baseline выполняется перед первым пресетом.
4. Между пресетами не менять сеть.
5. После завершения проверить сортировку рекомендаций.
6. Повторить с переключением адаптера между пресетами.

Критерий: при неизменной сети baseline переиспользуется; после смены адаптера или через пять минут baseline обновляется. Каждый пресет запускает и останавливает только собственный процесс.

## Сценарий I — старая история

1. Подложить копию `test-results.json` от ZUI 2.2.2.
2. Запустить приложение.
3. Открыть старый результат.
4. Экспортировать историю и проверить, что записи получили `schemaVersion: 2`.

Критерий: старая история не сбрасывается и прежние успешные проверки не превращаются в failed.

## Что приложить к отчёту об ошибке

- название и путь пресета;
- Classic или Zapret 2;
- экспортированный JSON результата;
- журнал канала «Тесты»;
- снимок деталей результата;
- указание, менялась ли сеть во время теста;
- оставались ли процессы winws/winws2 после завершения.
